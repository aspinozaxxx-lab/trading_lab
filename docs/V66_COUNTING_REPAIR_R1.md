# V66 R1: исправление только счётчика отчёта

2026-09-08. Первый V66 запуск завершился исключением `boolean value of NA is ambiguous`
в `position_counts`: денежный движок возвращает `pd.NA` для контракта плоской позиции.
Первый ledger был рассчитан в памяти, но его доходность не выводилась и не сохранялась:
`summarize` прервался до записи ledgers/metrics. Исходный каталог сохранён:
`/srv/trading_lab_data/runs/v66_fast_volume_contest_v1_307db9d6583e`.
Это технически незавершённый запуск, не экономический NO_GO.

R1 нормализует только имя отсутствующего контракта перед прежним счётчиком позиционных
эпизодов. Код исходных features/targets/ledger/gates и все численные параметры остаются
побайтно прежними. Отдельный wrapper временно подключает исправленный счётчик в своём
процессе; оригинальные файлы и неудачный каталог не изменяются. Два экономических
варианта и 48 сценариев остаются теми же; стратегия не подбирается заново.

Новый seal включает R1 config, wrapper, regression tests, эту записку и первоначальный
V66 seal. Output сохраняет родительский префикс `v66_fast_volume_contest_v1_`, но имеет
новый суффикс SHA R1; `protocol_id` в результате — `v66_fast_volume_contest_r1`.
Три regression tests воспроизводят ошибку, проверяют flat/смену знака/ролл и отсутствие
изменения исходной таблицы. Оригинальную попытку не повторять и не перезаписывать.
