# Synchronous scheduler interference — synthetic characterization

2026-09-08. No production runtime change or new economic hypothesis. The previous
quote-grouping fix addresses quote reuse order, not this separate scheduler issue.

Current runtime calls pump, then synchronously runs flow selection/capture/inference/
decisions. No pump tick occurs during that work. A slot may begin anywhere in E+3..E+10;
market packet capture alone permits120seconds. A late-starting slot can cross an
existing position's due time. It then fails its deadline, invalidates runtime and
requires reopen; even an immediate zero-overhead reopen may be outside due+30seconds.

New test drives the actual Runtime.tick/work/restart and actual Linux scheduler/anchor
journals with synthetic pump/slot callbacks and an artificial advancing clock:

| Start relative to E | Artificial slot duration | First pump after work/reopen |
| --- | --- | --- |
| +4m01s | 120s | on time when next tick is at due |
| +8m | 20s | on time when next tick is at due |
| +9m | 120s | due+60s, beyond30s |
| +9m59s | 40s | due+39s, beyond30s |

These are deterministic injected durations, NOT measured MOEX/network or server SLA.
No actual position/fill is generated by the pump callback. PASS means the expected
unsafe interference is reproduced, not readiness. Test includes failed-slot invalidation
and real account reopen; optimistic restart cannot erase elapsed time.

## Required direction

Do not relax quote age, backdate exits, extend the fixed30second fill window or ignore
unresolved positions. Separate potentially blocking source/model preparation from the
single authoritative execution/ledger owner, with bounded work, durable publication
and actual-time consumption. Alternatively a fully bounded cooperative implementation
must service the pump between work chunks and prove its longest non-yielding section.
An arbitrary earlier slot cutoff alone is not proof: source replay/fsync bounds remain
unknown and failure recovery still competes with exits.

Before activation, cover worker failure, stale publication, same-contract groups,
overlapping due times, bounded queue, restart and no shared-session/thread race. Keep
unchanged source/model hashes and fixed signal/execution economics. Actual network
latency remains future-only after F. F=null; no service/market/model run here.
