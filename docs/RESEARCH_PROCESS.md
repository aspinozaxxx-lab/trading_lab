# Порядок исследования после V62

Пользователь одобрил изменение подхода 2026-09-06. Цель остаётся прежней: относительно
предсказуемая доходность около 50% годовых, не менее 20%; она пока не достигнута.
Это изменение приоритетов работы, а не ослабление проверки или разрешение live trading.

## Что меняется

1. **Механизм до сложности модели.** Для каждой новой family назвать экономическую
   причину эффекта, информацию, известную до сделки, и способ исполнения. Сначала
   проверять покрытие данных, реалистичный размер возможности, оборот, комиссии,
   spread/slippage и ёмкость. Простое правило или малая модель служит baseline.
   Положительная линейная модель не является обязательным условием для проверки
   заранее обоснованной нелинейной гипотезы; отрицательный результат нельзя обходить
   произвольным увеличением числа моделей.
2. **Новая информация важнее нового имени.** Continuous timing, cross-market graph,
   net-value targets, corridor/distant stop и risk governors уже исследовались.
   Повторение требует содержательно иной информации или экономической механики,
   а не перестановки тех же порогов. Приоритет источникам order flow/depth,
   original-timestamp corporate events и defined-risk option surfaces. Для каждого
   явно отделять «источник существует» от «у нас есть пригодная история и права».
3. **Дополнение проверять на уровне источника прибыли.** Новому кандидату оценивать
   не только standalone CAGR, но и связь с существующим trading engine. Корреляция
   разных названий не доказывает диверсификацию. Снижение просадки добавлением cash
   не доказывает сохранение минимальных 20%. Условные summaries на плохих месяцах
   старой стратегии являются ex-post diagnostic, не разрешённым live switch.
4. **Дешёвый отсев и общий учёт.** Стадии предварительной проверки и полного обучения,
   baselines, thresholds и следующий допустимый шаг фиксируются до outcomes.
   Переиспользовать подходящий проверенный учёт/исполнение; новый engine писать лишь
   при обоснованно другой модели исполнения. Frozen code и canonical runs не
   рефакторить задним числом. Не строить универсальный framework вместо проверки
   конкретной доступной гипотезы.

Все прежние правила causal information, разделения features/labels, protected 2026,
byte seals, costs и независимой проверки сохраняются. Новый historical diagnostic
не является unseen подтверждением. Не выбирать weights/assets/years/hours по нему.

## Первый практический шаг: V63

Разложить V41/V49/V60 относительно общего V39 и cash-carry parent: торговый gross PnL,
издержки, модельный доход свободных денег, вклад cash sleeve, все календарные годы и
связь месячных результатов. Сравнение в рублях на стартовый миллион; CAGR не складывать.

Код V49/V60 сохраняет в `exact_futures_nav` ту же combined NAV с collateral income,
что и в `combined_nav`. Это название нельзя использовать для выделения «чистых фьючерсов».
V63 берёт yearly futures summaries и recorded order costs; не пересчитывает trades.
Cash overlay включает compounding, поэтому его residual trade contribution — часть
исходной normalized конструкции, а не новый backtest исходных integer размеров.

Протокол: `configs/v63_frozen_profit_attribution_v1.yaml`. Источник статуса и canonical
пути — [STATUS.md](STATUS.md). Вывод V63 должен определять следующий разрешённый
исследовательский шаг, но не может сам дать GO для цели 20%/50%.

## Продолжение после завершённого V63

V63 показал сильное сходство результатов лидеров. Новый приоритет — ранее отложенная
гипотеза о дисбалансе агрессивных сделок относительно глубины стакана. Новая информация
может помочь краткосрочному timing; её доходность после затрат и независимость от V49
ещё предстоит проверить, а не предполагать по другому названию модели.

Bounded source feasibility 2026-09-06 не нашла TradeStats/OBStats в проверенном
forward root; там только delayed FUTOI. Следующий конкретный шаг — ограниченный
тестовый доступ и проверка истории/прав по [DATA_ACCESS_REQUESTS.md](DATA_ACCESS_REQUESTS.md),
с отдельной авторизацией на внешний запрос и без покупки по умолчанию. Не строить
новый engine до получения пригодного sample. Пятиминутные агрегаты не заменяют
отдельные события стакана, causal BBO для исполнения или данные об очереди.

2026-09-07 пользователь отложил AlgoPack и поручил другие гипотезы. Первый бесплатный
эксперимент — [V64, налоговый календарь SI](V64_TAX_CALENDAR.md): новое calendar
information set, заранее фиксированные основное/контрольное окна, три era и costs.
Он не использует V19 outcomes для выбора дат или знака. V64 уже завершён один раз:
`NO_GO`, audit 156/156. Primary CAGR по eras 2,82% / 2,03% / −0,16%; в recent результат
хуже контрольного окна. Окно/знак/плечо не менять, control не продвигать как новый alpha.
Полноценную нейросеть по этому отрицательному screen не строить. Подписку/paid collector
пока не подключать; ранее отправленное письмо не дублировать.

Следующее независимое information set — официальные объявления о пересмотре индексов:
гипотеза ожидаемого спроса пассивных фондов после подтверждённых включений. Пока сделана
только [проверка доступности примеров](MOEX_INDEX_REBALANCE_SOURCE.md), без prices/PnL.
Сначала нужен source-only seal и проверка полного event/revision корпуса; шесть страниц
для трёх событий не означают шесть сделок или достаточное историческое покрытие.
Учитывать waitlists, повторные публикации, redomiciliation/halts и исторические бумаги.
После пригодного источника — отдельный заранее фиксированный event screen с control,
издержками и всеми доступными eras, а не обучение на удачных поисковых примерах.

Позднее 2026-09-07 пользователь купил AlgoPack и предоставил key. Это новое внешнее
состояние снимает credential blocker и возвращает flow/depth source на первый план.
Следовать [ALGOPACK_HISTORICAL_SOURCE.md](ALGOPACK_HISTORICAL_SOURCE.md): сначала
отдельный sealed historical metadata inventory, затем sample/история и экономический
протокол. Не использовать старый latest=1 forward collector как historical downloader.
Индексная ветка остаётся незапечатанным prototype, не запускается параллельно по умолчанию.

2026-09-08 подготовка AlgoPack завершена, запуск назначен на будущее время. Пользователь
справедливо указал, что постоянный опрос ожидающего таймера не является поиском дохода.
Ручной минутный опрос прекращён; автономный запуск не меняется. Исследовательское время
возвращено следующему независимому information set: bounded source-only
[sample индексных объявлений](MOEX_INDEX_NEWS_SAMPLE_V1.md). Сначала9ранее известных
публикаций/18requests для проверки API/schema/revisions, не полный framework и не PnL
по удобным примерам. Полный корпус и экономический screen остаются отдельными gates.
