# Воронка проверки стратегий

Пользователь2026-09-08 потребовал быстрый конкурс гипотез и последовательные уровни
проверки. Главный результат — экономические выводы и отсев, не количество кода/тестов.
Цель20–50% годовых сохраняется; ни один промежуточный PASS не означает её достижения.

| Уровень | Работа | Переход дальше |
| --- | --- | --- |
| 1. Быстрый конкурс | Несколько различных механизмов, простой baseline, имеющиеся разрешённые данные, комиссии, просадка и все результаты. Без обучения большой модели или нового сборщика. | Заранее объявленные дешёвые gates; только `STAGE2_CANDIDATE`, не прибыльная стратегия. |
| 2. Устойчивость | Детально проверить только кандидатов: ошибки учёта, временные splits, плохие годы, стресс затрат, несколько испытаний и зависимость от старого лидера. | Не держится на одном периоде/случайном выборе, есть экономический запас. Уже просмотренную историю не называть независимой. |
| 3. Исполнимость | Котировки BID/OFFER, размер, комиссии, margin, задержки и пропуски. Использовать существующий контур. | Положительный результат сохраняется при реалистичном исполнении; нет необъяснённого риска. |
| 4. Демо | Зафиксированная стратегия на новых данных и виртуальном капитале; без реальных денег. | Сравнение ожидаемого и фактического результата, устойчивости и покрытия за достаточный период. |

До первого прогона достаточно короткого config с правилами, периодами, контролями,
затратами и критериями плюс hash кода/входов. Не строить отдельную инфраструктуру для
каждой идеи. Слабую гипотезу закрывать, а не бесконечно оптимизировать её параметры.
В журнале хранить номер уровня, результаты всех кандидатов и конкретную причину отсева.

V65 — первый пакет этого процесса:4calendar-mechanism hypotheses ×2arms ×3eras
(2008–2011/2012–2017/2018–2025) ×2costs. Используется готовый daily portfolio ledger и
input manifests V64; налоговая стратегия V64 и её результаты не повторяются.
Calendar-only правила не подбираются по ценам. Это development screen с research-proxy
исполнением, не unseen holdout и не доказательство реального механизма.
Предположение по месячному эффекту мотивировано
[исследованием McConnell/Xu](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=917884);
weekly oil arm использует лишь обычную среду из
[расписания EIA](https://www.eia.gov/petroleum/supply/weekly/schedule.php), не исторический
exact release calendar. Роллирование планировщика не доказывает реальный flow.

Для V65 подробные gates находятся в `configs/v65_fast_calendar_contest_v1.json`.
Порог5% на первом уровне нужен лишь для отбора потенциального компонента; цель минимум20%
им не заменяется. Отдельно показываются historical20/50 flags, goal_verified всегдаfalse.
Первый уровень должен закончиться таблицей результата, а не обещанием следующей проверки.

Подготовленный source sample индексных новостей оставлен незапущенным. AlgoPack paper
остаётся отдельным prospective экспериментом; его запланированный запуск не означает,
что он прошёл эту воронку. Подключение к внешнему broker demo требует его реквизитов;
реальные сделки по-прежнему не разрешены.
